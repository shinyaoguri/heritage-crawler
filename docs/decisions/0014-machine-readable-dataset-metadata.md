# 0014: データリポジトリに機械可読なメタデータを置き、出典の利用日は実測から出す

## 状態

承認済み (2026-08-12)

## 文脈

[0007](0007-redistribute-text-with-attribution.md) は、文字情報を再配布する条件と
して出典表記の掲出を決めた。書式には**利用日**が含まれる。

```
出典：「国指定文化財等データベース」（文化庁）
（https://kunishitei.bunka.go.jp/）（2026年8月12日に利用）
上記を加工して作成
```

ところが現状、この日付と収録件数は各データリポジトリの `README.md` と `LICENSE`
の散文の中にしかなく、手で書いたものである。**規約が求める値が手書きで置かれて
いる**ということは、月次の差分更新 (Issue #10) が動き出した瞬間から、更新のたびに
静かに嘘になっていくということでもある。ドリフトがそのまま規約違反になる値は
これだけで、他の記述とは危険度が違う。

正しい日付は既に実測されている。`src/heritage_crawler/cache.py` の
`DetailEntry.fetched_at` が詳細ページ 1 件ごとの取得日時を ISO 8601 (UTC) で
持っており、組み立ては同じエントリを既に触っている。新しい取得も新しい依存も
要らず、書き出すだけで実測値になる。

もう一つ、データを読む側から見た問題がある。出力は分類をまたいでキーを正規化して
あるが ([0008](0008-normalize-schema-detail-page-wins.md))、**もとの呼び名は分類ごとに
違う** — 同じ `designation_number` を 101 は「登録番号」、102 は「指定番号」、
103 と 401 は「告示番号」と呼ぶ。対応表を持っているのはクローラーだけなので、
読む側は独自の和訳表を抱えることになり、原文の表記が変わっても追随できない。
種別の語彙も同様で、1 データリポジトリあたり 3〜30 種と幅があり、
[0013](0013-delete-the-repository-without-data.md) で 10 個に確定したリポジトリの
どれを開くかで中身が変わる。

## 決定

各データリポジトリのルートに `meta.json` を書く。生成は
`src/heritage_crawler/metadata.py`、呼び出しは `src/heritage_crawler/export.py`。

- **利用日は詳細ページを取得した日**とし、そのデータセットで最も新しい
  `fetched_at` を日本時間に直した日付を採る。組み立てを走らせた日ではない —
  `build-records` はキャッシュだけを読むので ([0006](0006-run-initial-crawl-locally-updates-on-actions.md))、
  古いキャッシュから組み立て直せば実行日は実態と合わない。UTC のまま日付を切ると
  日本の夕方以降に取得したぶんが 1 日前にずれるため、日本時間に直してから切る
- **出典表記は組み立てて載せる。**利用日を持つだけでなく、そのまま掲出できる
  3 行を `attribution` に入れる。読む側が書式を再現しなくてよい
- **表示名 (`labels`) は実測して載せる。**原文ラベルを持つキーは組み立て中に
  拾い、番号だけが違う欄 (種別１ / 種別２) は番号を落として 1 つに畳む。原文
  ラベルを持たないキー (緯度経度・解説文・URL) の呼び名は
  `src/heritage_crawler/record.py` の `DERIVED_LABELS` で決める。**表示名も
  スキーマの知識なので、スキーマの正本と同じ場所に置く**
- **語彙 (`facets`) は取りうる値が少ないキーだけ**を件数つきで載せる。名称や
  解説文まで数えると `meta.json` がデータの写しになる。値が 1 つも無いキーは
  出さない (読む側が空の絞り込みを描かないように)
- **件数は書き出したレコードから数える。**数える場所を 1 つにして、出力と
  `meta.json` がずれる余地を作らない
- `schema_version` を持つ。上げるときはこの ADR の系列に記録する
- **ファイルごとのハッシュは載せない。** git が内容ハッシュを持っており、
  載せれば月次の差分で `meta.json` が毎回全面書き換えになるだけになる
- **生成物は決定的にする。**実行日時のような、入力が同じでも変わる値を入れない。
  データが変わらない月に差分が立たないようにする

## 影響

- `build-records` の出力が、データリポジトリ 1 つにつき 1 ファイル増える。
  `src/heritage_crawler/export.py` は `DetailCache.entries` を参照するようになる
  (これまでは `is_done` と `read_html` だけだった)
- **`meta.json` の有無がデータセットの有無と等価になる。**データを読む側は
  リポジトリ名を並べたハードコードの表を持たずに済み、新しい種別が増えても
  追随できる
- 読む側は分類ごとの差異 (呼び名・語彙・キー集合) を知らなくてよくなる。
  [0004](0004-output-jsonl-per-prefecture.md) の都道府県分割はそのままで、
  どのファイルに何件あるかは `files` から読める
- **`README.md` の件数と利用日は手書きのまま残る。**この ADR は機械可読な正本を
  置くところまでで、散文の側を追随させる仕組みは別に決める。正本ができたので、
  次に触るときは `meta.json` から生成できる
- 出典表記の掲出先として [0007](0007-redistribute-text-with-attribution.md) が
  挙げていたのは README と LICENSE、および配布物だった。`meta.json` はそこに
  機械可読な形を 1 つ足すもので、掲出義務そのものは変わらない
