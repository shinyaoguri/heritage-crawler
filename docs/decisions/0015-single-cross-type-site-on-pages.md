# 0015: データ閲覧サイトは種別横断の 1 つにして専用リポジトリの Pages に置く

## 状態

承認済み (2026-08-12)

## 文脈

データは 10 のリポジトリへ出力され ([0013](0013-delete-the-repository-without-data.md))、
初回の全件取得は完走した。しかし**中身を見る手段が「JSON Lines を自分で読む」しか
ない**。地図・一覧・検索でデータを確かめられるサイトが要る。

置き場の候補は 3 つあった。

**(A) データリポジトリ 10 個それぞれにサイトを置く。** 種別ごとに URL が独立し、
データとサイトが同じコミットに入る。ただし
[0001](0001-split-repositories-by-heritage-type.md) が「種別ごとに分けるのは
データであってコードではない。種別ごとにクローラーを複製すると同じ修正を N 箇所に
当てることになる」と決めており、**サイトはコードなのでこの論証がそのまま当たる**。
生成物をコミットする形にすると、
[0004](0004-output-jsonl-per-prefecture.md) が JSON Lines を選んだ理由 (差分が
行単位で読める) が月次の更新で崩れる — データ 1 行の変更を見たいのに、サイトの
生成物が差分に混ざる。

**(B) クローラー自身にサイトを持たせる。** 依存 0 の Python リポジトリに
JavaScript のツールチェインを持ち込むことになり、CSS を 1 行直すたびに Python
3.12/3.13/3.14 のマトリクスが回る。クローラーは個人アカウント、データは
`code4heritage` org にあるので、サイトの同一性の置き場としても合わない。

**(C) 種別横断のサイトを 1 つ置く。**

横断の必要性はデータの実態から出ている。**同じ棟が複数のデータセットに現れる
複合指定が 114 件ある** (実測。23,855 行 / 異なり 23,741 件)。旧浜離宮庭園は特別
名勝と特別史跡の両方に同じ行がある ([0012](0012-crawl-monuments-and-route-by-kind.md))。
種別ごとのサイトでは「これは特別史跡でもある」を表現する手段がない。利用者の問い
(「京都府にある文化財」「1950 年代に指定されたもの」) も種別で切れていない。

規模も小さい。全 JSON Lines を gzip して約 7 MB、地図に必要な項目だけなら
gzip 400 KB 台に収まる。1 サイトに全部載る。

前提として、GitHub Free の org は **public リポジトリでしか Pages を使えない**。
公開してよいことは [0007](0007-redistribute-text-with-attribution.md) で決着済み。

## 決定

**`code4heritage/heritages` を新しく作り、そこに 1 つだけサイトを置く。**
データリポジトリには Pages を置かない。

- **org サイト (`code4heritage.github.io`) にはしない。**org サイトはルート URL に
  出るので、将来どれかのデータリポジトリで Pages を有効にすると、そのパスが
  ルートサイトを上書きする。`heritages` なら `/heritages/` の下に閉じ、衝突が
  原理的に起きない
- **ルーティングはハッシュにする。**ベースパスの下で履歴 API を使うとベースパスの
  剥がしが要る。ハッシュならそれも、Pages がクライアントのパスに 404 を返す問題への
  細工も要らない。データの取得もすべて相対パスにして、ベースパスに依存させない
- **ビルド成果物はコミットしない。**Pages のソースを GitHub Actions にして、
  ビルド結果をアーティファクトとして配信する。これで
  [0004](0004-output-jsonl-per-prefecture.md) の差分の読みやすさを保ったまま、
  サイトの履歴にもソースだけが残る
- **データセットは `meta.json` の有無で見つける** ([0014](0014-machine-readable-dataset-metadata.md))。
  リポジトリ名を並べた表をサイトに持たせない。種別が増えてもサイト側の変更は要らない
- **JSON Lines は変換せずそのまま配る。**サイトが見せているのはデータリポジトリの
  あの行そのもの、と言える状態にする。地図用の軽い索引だけを別に生成する
- **クローラーからサイトへの通知 (`repository_dispatch`) は入れない。**個人
  アカウントから org へ dispatch するトークンが要る。Issue #10 が既に必要とする
  権限を、反映を数時間早めるためだけに広げない。public リポジトリの Actions は
  分数無制限なので、月次で空振りさせて困らない

## 影響

- **データリポジトリ 10 個を public にする。**Pages の前提であり、
  [0007](0007-redistribute-text-with-attribution.md) の判断の実行にあたる。
  あわせて Free プランの public でだけ使える ruleset を入れられるようになる
  ([0009](0009-output-to-existing-per-type-repositories.md) が「public 化した
  時点で入れられる」と書いていたもの)
- データリポジトリの月次の差分は JSON Lines の行だけのまま保たれる
- サイトのコードは MIT、データは文化庁の利用規約という 2 層の表記になる
  ([0007](0007-redistribute-text-with-attribution.md))。**画像は持てない**ので、
  地図とテキストだけで見せる設計になる
- **どのデータリポジトリでも Pages を有効にしない。**有効にすると
  `/heritages/` 以外のパスを占めることになり、将来 org サイトを足したときに
  ルートを上書きする
- 種別ごとの独立した URL が要るようになったら、そのときデータリポジトリに転送だけの
  1 ファイルを置けばよい。統合サイト側の資産は 1 本のまま増えない
