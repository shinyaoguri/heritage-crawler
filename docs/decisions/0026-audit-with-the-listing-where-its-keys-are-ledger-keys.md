# 0026: 一覧と突き合わせられるかは、展開の有無ではなく一覧のキーが台帳に載るかで決める

## 状態

承認済み (2026-08-24)。[0017](0017-audit-completeness-with-the-search-listing.md) の
「棟に展開される分類は対象外」と「回収で地域欄を埋める」を置換する。網羅性を一覧で
確かめること・回収 CSV をまるごと書き直すこと・送信値を推測しないことは変えない。

## 文脈

[0017](0017-audit-completeness-with-the-search-listing.md) は、地域で引けない指定を
検索結果一覧から回収する仕組みを決めたとき、**棟に展開される分類 (102) を
`Category.expands_to_buildings` で弾いた**。理由は「複数棟の指定は詳細ページへ
直接リンクされない (棟一覧のモーダルになる)」で、一覧が指定単位・CSV が棟単位という
単位の違いも根拠に挙げていた。

この条件は 201 (国宝・重要文化財（美術工芸品）) を巻き添えにしていた。201 は
所有者住所（所在都道府県）で分割するが、**この欄が空の指定はどの `seat_pref` でも
引けない** (Issue #83)。全国 CSV は 11,442 行で 2,000 件超のため 504 になり
([0011](0011-limit-rate-and-verify-error-pages.md))、代替も無い。一覧が使えれば
回収できるのに、フラグ一つで通信する前に断られていた。

2026-08-24 に両分類の一覧を全ページ辿って測った。

| | 件数表示 | 集めた行 | 台帳のキー | 一覧にあって台帳に無い | 台帳にあって一覧に無い |
|---|---|---|---|---|---|
| 201 | 10,954 | **10,954** (110 ページ) | 11,433 | **92** | 571 |
| 102 | 2,633 | **1,907** (27 ページ) | 5,587 | 0 | 3,680 |

- **201 の一覧は件数表示と完全に一致し、重複も無い。** 1 指定が複数の件に展開されるが、
  一覧の行はその 1 件目へ直接リンクしていて、キーは台帳に載る。だから
  「一覧にあって台帳に無い」92 件を取りこぼしとして 1 件ずつ名指しできる
- **102 の一覧は 2,633 件のうち 1,907 行しか読めない。** 複数棟の指定が詳細ページへ
  リンクを持たないためで、0017 の見立てはこちらでは正しかった。読めた行はすべて
  台帳にあるが、**読めなかった 726 指定を見ていない**ので網羅性の担保に使えない
- **余りは分類の性質で意味が変わる。** 201 の 571 件は複数件の指定の 2 件目以降で、
  指定解除ではない。「指定解除を疑う」と報告し続けると毎週の誤報になる

つまり弾く条件は**二つの別の性質を兼ねていた** — 「1 指定が複数行に展開される」ことと
「一覧のキーが台帳のキーに載らない」ことである。201 は前者だが後者ではない。

回収そのものにも実測で分かったずれがある。0017 は回収 CSV に一覧の地域欄を写すと
決めていたが、**一覧の列見出しは全分類で「都道府県」なのに、CSV の 12 列目の意味は
分類で変わる** (#74)。201 の取りこぼし 92 件は一覧に「宮城県」「東京都」と出ている
のに CSV 側の欄は空で、詳細ページ (`201/2713`・`201/6421`) の所在都道府県も所在地も
空だった。写せば意味の違う欄の値が台帳に紛れ込む。

## 決定

- **一覧と突き合わせられるかは `Category.audits_with_listing` で持つ。**
  「一覧のキーが台帳のキーに載るか」だけを表し、展開の有無 (`expands_to_buildings`) とは
  独立させる。既定は真で、102 だけ偽 (上の実測)。`fetch_listing` と `audit-listing` は
  この属性を見て、載らない分類は通信する前に断る
- **`expands_to_buildings` は元の役目に戻す。** CSV のキーの異なり数を全国件数と
  直接比べられるか (`ledger.summarize`) だけに使う。201 はここでは今までどおり比べられない
- **余りは分類ごとに読み方を書き分ける。** 展開される分類では「1 指定が複数行に
  展開されるぶん」と注記し、指定解除を疑わせない。取りこぼしの証拠になるのは
  `missing` の側だけ
- **回収では地域欄を写さない。** 埋めるのはキー・名称・緯度経度だけにする。CSV から
  下流へ渡るのは緯度経度だけなので ([0008](0008-normalize-schema-detail-page-wins.md))
  出力は変わらず、意味の違う欄へ値を移さずに済む
- **場所の無い指定に場所を作らない。** 所在都道府県も所在地も空の指定は
  `record.resolve_location` が「地域を定めない」へ置き、`build-records` の報告に
  「都道府県が 1 つに決まらなかった」として出る。一覧の都道府県列から推定して
  47 都道府県のどれかへ寄せることはしない

## 影響

- 201 の 92 件が台帳へ回収され、詳細まで取れて出力に載る。**201 の穴が塞がる** (#83)
- 週次の `audit-listing --recover` に 201 の 112 リクエスト (110 ページ + 検索 + 表示件数)
  が加わる。1 req/s で約 2 分で、ジョブ上限には遠い
- 102 の網羅性は従来どおり件数表示の差でしか見られない。**この分類だけは一覧でも
  台帳でも確かめられない**ので、消えた指定の判定は詳細ページでの実在確認
  ([0021](0021-record-removals-with-evidence.md)) が唯一の証拠になる
- 回収 CSV の地域欄が空になる。401 の回収行は元から空だったので既存の出力は変わらない
- 「一覧が件数表示と合わない」報告 (`Listing.is_consistent`) は残す。**102 で 1,907 /
  2,633 と出たように、相手の作りが変われば同じ形で気付ける**
