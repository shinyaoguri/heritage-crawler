# 0000: 設計判断を ADR で記録する

## 状態

承認済み (2026-08-11)

## 文脈

このリポジトリは要件議論から始まるプロジェクトで、データ取得戦略・
スキーマ設計・リポジトリ分割など、後から「なぜそうしたか」を問われる
判断が多く発生する見込み。セッションの記憶はリセットされる前提のため、
判断の経緯をリポジトリ内に恒久的に残す仕組みが最初から必要になる。

## 決定

設計判断は docs/decisions/ に連番の ADR (Architecture Decision Record)
として記録する。各 ADR は 状態 / 文脈 / 決定 / 影響 の 4 節で構成する。
決定を覆すときは元の ADR を書き換えず、状態を 廃止 / 置換 に更新して
新しい ADR を起こす。

## 影響

- 設計判断を伴う PR は対応する ADR を同じ PR に含める
- 記憶ゼロの状態でも docs/decisions/ と Issue を読めば判断の経緯を
  追跡できる
- 軽微な実装判断まで ADR にはしない (PR 本文とコミットログで足りる
  粒度は ADR を起こさない)
