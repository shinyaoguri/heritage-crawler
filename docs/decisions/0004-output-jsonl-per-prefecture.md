# 0004: 成果データは都道府県ごとの JSON Lines として出力する

## 状態

一部置換 (2026-08-12) —
[0009](0009-output-to-existing-per-type-repositories.md) による。
ファイル配置 (`data/<分類コード>/<都道府県>.jsonl`) は 0009 が置換した
(出力先が種別ごとのリポジトリに分かれたため)。JSON Lines で 1 行 1 棟、
キーで安定ソートする決定は有効。

## 文脈

このプロジェクトの価値は、文化財データを GitHub に記録することで
**「いつ何が変わったか」が履歴として追える**点にある。したがって出力形式は
差分の読みやすさを第一に選ぶ。

候補は 3 つあった。

- 1 レコード 1 JSON ファイル — 個別の変更履歴は最も追いやすいが、
  棟単位で 2 万ファイル規模になり、リポジトリとして扱いにくい
- 単一の CSV — 取得元に近く扱いやすいが、附指定など入れ子の構造を
  表現しにくい
- 都道府県ごとの JSON Lines — 差分が行単位で読め、ファイル数も抑えられる

また [0002](0002-two-stage-fetch-csv-then-detail.md) で取得の分割軸を
都道府県としたため、出力の単位を揃えると取得と出力が 1:1 で対応する。

## 決定

分類コードと都道府県でディレクトリとファイルを分け、JSON Lines で出力する。

```
data/<分類コード>/<都道府県コード>_<ローマ字表記>.jsonl
例: data/102/01_hokkaido.jsonl
```

1 行 1 棟とし、キーは `(台帳ID, 管理対象ID)` とする。行の並び順は
キーで安定ソートし、取得順に依存させない (順序の揺れを差分に出さないため)。

## 影響

- 差分レビューで変更された文化財が行単位で判別できる
- 取得の単位 (分類 × 都道府県) と出力ファイルが 1:1 で対応するため、
  部分的な再取得と再出力がしやすい
- JSON Lines のスキーマ (CSV 由来の項目と詳細ページ由来の項目をどう
  統合するか、項目名を原文のままにするか正規化するか) は未決。
  Issue #1 で継続議論する
- 出力先リポジトリは [0001](0001-split-repositories-by-heritage-type.md)
  のとおりクローラー本体とは別リポジトリになる
