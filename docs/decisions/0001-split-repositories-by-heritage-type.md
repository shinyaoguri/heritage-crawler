# 0001: 文化財の種別ごとにリポジトリを分けて個人アカウントで管理する

## 状態

承認済み (2026-08-11)。未決だった分割の単位とこのリポの位置付けは
2026-08-11 の要件議論で決定し、本 ADR に反映済み

## 文脈

国指定文化財等データベースは建造物以外にも多数の種別 (美術工芸品・
史跡名勝天然記念物など) を持ち、種別ごとにデータ項目・取得方法・
更新頻度が異なる。単一リポジトリに全種別を詰め込むと、データ量と
関心事が混ざり、履歴も追いにくくなる。

当初は code4heritage organization での管理を想定したが、org の
Free プランでは private リポの ruleset (main 保護・PR 必須) と
auto-merge が使えないことが判明し、org で管理する必然性も無かった
ため、個人アカウントへ移行した (2026-08-11 transfer 実施)。

## 決定

個人アカウント (shinyaoguri) で管理し、**クローラー本体とデータを
別リポジトリに分ける**。

- `heritage-crawler` (このリポ) — 全種別に対応するクローラー本体。
  種別ごとにクローラーを複製しない
- 種別ごとのデータリポジトリ — クローラーの出力先。建造物系
  (分類コード 101 / 102 / 103) を最初のデータリポとする

種別ごとに分けるのは**データであってコードではない**。データベース上の
取得処理は分類コードが違うだけでほぼ共通であり、種別ごとにクローラーを
複製すると同じ修正を N 箇所に当てることになるため。

## 影響

- 各種別のデータは独立した履歴を持ち、リポ単位で公開・共有を判断できる
  (公開方針は [0005](0005-private-until-license-confirmed.md) を参照)
- クローラーは分類コードをパラメータとして受け取る設計にする
- データリポジトリの作成は、クローラーが出力を持てる段階になってから行う
  (空のリポジトリを先に作らない)
