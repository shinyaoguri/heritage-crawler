# 0028: 確認日は渡さず、データリポジトリから読ませる

## 状態

承認済み (2026-08-24)。[0023](0023-stamp-every-check-into-the-data-repositories.md)
の「heritages への確認日はそのまま渡す」だけを改める。`status.json` を毎週書くこと・
日付を 2 つ並べること・**書くのは週次だけ**はそのまま引き継ぐ。

## 文脈

0023 は確認日に置き場を 2 つ与えた。**各データリポジトリのルートの `status.json`** と、
**heritages のリポジトリ変数 `LAST_CHECKED_DATE`**。前者はリポジトリ 1 つだけを見て
「静かなのか止まっているのか」を判定するため、後者はサイトの「最終確認」を出すためで、
週次が毎週その両方へ同じ日付を書く形にした。

**変数の経路が動いていない。** 週次はサイト用のトークンに Variables の書き込みを
求めているが、`actions/create-github-app-token` には **variables を絞って要求する入力が
無い** (`permission-*` の入力 57 個に variables 系は 1 つも無い)。書いても無視され、
2026-08-22 の実行は「サイト用のトークンを発行」の段で落ちた
([#94](https://github.com/shinyaoguri/heritage-crawler/issues/94))。

絞りを捨てて App が持つ権限をそのまま渡すトークンにすれば動く。だがそれは
「**App が持つ権限をそのまま配らず、行き先と用途で絞る**」という
[0020](0020-check-weekly-by-diffing-the-ledger-csv.md) 以来の週次の作りを崩す。
権限の話だけなら、崩さない直し方があるか先に見るべきだった。

**そもそも変数は二重帳簿だった。** 同じ日付が `status.json` にも書かれている。
変数の側だけが権限を要求し、変数の側だけが古くなりうる — サイトのコードを直しただけの
回や保険 cron の回は、週次が次に書き込むまで前の値が残る。0023 自身がこう予告していた
— 「将来 heritages が各リポジトリの `status.json` を読めば、`LAST_CHECKED_DATE` 変数は
畳める。今回は触らない (サイト側の変更になるため)」。

## 決定

**確認日を渡さない。heritages が各データリポジトリの `status.json` から読む。**

- **週次がするのは押すことと起こすことだけ。** `gh variable set LAST_CHECKED_DATE` を
  やめ、`deliver.yml` への `--field checked-date` もやめる。残るのは
  `gh workflow run deliver.yml` の 1 行
- **サイト用のトークンは `permission-actions: write` だけ**になる。絞りを保ったまま
  発行が通る
- **採るのは一番古い確認日** (heritages 側の `datasets.oldest_checked_date`)。
  どれか 1 つのリポジトリへの push が落ちた週は、そこだけ確認日が進まない。新しい方を
  採ると「全部確かめた」と読めてしまい、止まっていることが隠れる
- **`status.json` を持たないリポジトリは判定から外す。** 週次が一度も届いていない器は
  ありうるので、欠けは配信を止めず warning で報せる (heritages 側の `checks`)
- **要件は順序だけになる** — 押すのが先、起こすのが後。日付を運ばないので、
  起こし損ねた回に「渡せなかった値」は残らない

## 影響

- **サイトの「最終確認」が起こされ方によらず正しくなる。** push で配信し直した回も、
  保険 cron が拾った回も、データが持っている日付が出る
- **週次が heritages を起こせなかった週の被害が「配信の遅れ」だけになる。** 0023 の
  形では、そこに「確認日が古いまま残る」が加わっていた
- **App の `actions_variables: write` は使わなくなる** (org の設定から外してよい)。
  週次が heritages に要るのは `actions: write` 1 つ
- 確認日の置き場が `status.json` 1 つになる。**二重帳簿が消える**
- **移行の途中では確認日を持たないリポジトリが残る。** 週次が押せたのは 10 リポジトリ
  だった頃の 1 回だけなので、2026-08-24 時点で 26 個中 16 個が `status.json` を持たない。
  次の週次で揃う。それまでは heritages 側の warning に並ぶ
